# Glossary

Plain-language definitions for terms used in this project.

## Application
A program people use directly, such as the Customer Web application.

## API
A defined way for one software system to ask another software system to perform an operation or provide information.

## Backend
The server-side part of the application that handles business rules, data, security, and APIs.

## Catalog
The system that describes products, categories, attributes, variants, and related product information.

## CI
Continuous Integration. Automated checks that run when code changes.

## CD
Continuous Delivery/Deployment. Automated processes that move verified software toward or into an environment.

## Control flow
The path a request follows through a program.

## Database
A structured system used to store and retrieve application data.

## Event
A recorded fact that something happened, such as "OrderPlaced".

## Module
A business capability with a defined boundary and contract.

## Search index
A specially structured copy of data optimized for fast searching. It is normally not the source of truth.

## Source of truth
The authoritative system whose value wins when two systems disagree.

## Taxonomy
A hierarchy used to organize things into categories and subcategories.

## Product type
A definition of what kind of product something is and which attributes it normally has.

## Variant
A specific purchasable form of a product, such as a T-shirt in size L and blue.

## Reconciliation
A process that compares systems and repairs or reports differences.

## Customer cloud
A deployment model in which the customer's cloud account and infrastructure host the application and its data.
